# Contributing

## Requirements

- Go 1.27.4 or newer (`go.mod`).
- [mise](https://mise.jdx.dev), which installs the pinned tools in `mise.toml`: golangci-lint v2 (configured by
  `.golangci.yml`), govulncheck, goreleaser and svu.
- [markdownlint-cli2](https://github.com/DavidAnson/markdownlint-cli2) and
  [editorconfig-checker](https://github.com/editorconfig-checker/editorconfig-checker) for the Markdown and
  whitespace rules in `.markdownlint.json` and `.editorconfig`.
- For a smoke test: rclone, to serve a local WebDAV share. For the Linux path on a Mac: Docker (OrbStack works).

## Layout

| Path                  | What it holds                                                                   |
|-----------------------|---------------------------------------------------------------------------------|
| `main.go`, `cmd_*.go` | The CLI: `mount`, `unmount`, `status` and the hidden `daemon` command           |
| `internal/config`     | Config file, paths, password resolution                                         |
| `internal/server`     | The daemon: rclone VFS, the NFSv4 server, its access checks, the control socket |
| `internal/fsys`       | billy filesystem for go-nfs: VFS adapter, in-memory sidecars, per-file locks    |
| `internal/platform`   | `mount_nfs` / `mount -t nfs`, unmounting, reading the mount table               |
| `third_party/go-nfs`  | Patched go-nfs; see [go-nfs-UPSTREAM.md](third_party/go-nfs-UPSTREAM.md)        |

## Build, test, lint

`mise.toml` pins the tools (Go itself comes from `go.mod`) and holds the tasks CI runs, so `mise run all` locally
is the same gate as CI:

```sh
mise install         # golangci-lint, govulncheck, goreleaser, svu, gobco at the pinned versions
mise run all         # lint, test-race, vuln, build: the CI gates

mise run build       # ./davdrive for this platform
mise run test        # includes TestConcurrentWrites, about 20 s
mise run test-short  # skips it, for a quick loop
mise run test-cov    # statement coverage, then each branch the tests never took (gobco)
mise run lint        # golangci-lint for darwin and linux, reporting only
mise run vuln        # govulncheck: reachable vulnerabilities only

markdownlint-cli2 README.md CONTRIBUTING.md third_party/go-nfs-UPSTREAM.md
editorconfig-checker
```

The lint runs for both `GOOS` values: `internal/platform` has a darwin and a linux implementation, and each build
sees only one of them. `.golangci.yml` sets `fix: true`, so a plain `golangci-lint run ./...` rewrites the files
it can fix (formatting, comment punctuation, blank lines); review those changes before committing. `mise run lint`
passes `--fix=false`, because a gate that fixes instead of reporting passes on code it just rewrote. A `//nolint`
needs the linter name and a reason (`nolintlint` enforces both).

## Releasing

Releases use SemVer tags (`v0.1.0`): the Go module proxy only recognises `vMAJOR.MINOR.PATCH` tags as module
versions. On a clean `main`, `mise run release <patch|minor|major>` fetches the remote's tags, asks
[svu](https://github.com/caarlos0/svu) for the next version, tags and pushes it. Before the first tag, `minor`
gives `v0.1.0`. From v2 on, Go needs the major version in the module path (`github.com/ivuorinen/davdrive/v2`),
so the task refuses a major bump to v2 or later until `go.mod` says so.

The tag starts `.github/workflows/release.yml`, which runs GoReleaser (`.goreleaser.yaml`): it builds darwin and
linux binaries for amd64 and arm64, signs the checksums with cosign keyless signing, and attaches `LICENSE` and
`THIRD_PARTY_NOTICES.txt`.

The notices file is generated by `tools/notices.sh` (go-licenses with `tools/notices.tpl`) in GoReleaser's
`before` hook. MIT, BSD and Apache-2.0 require the licence texts to ship with binaries, so a release without it
would breach them. `mise run notices` writes it to `build/` locally, and `mise run snapshot` builds the whole
release into `dist/` without signing or publishing.

## The vendored go-nfs

`third_party/go-nfs` is upstream go-nfs plus the patch files next to it, and nothing else. Do not edit it by hand:
change or add a patch, then rebuild the directory with the procedure in
[go-nfs-UPSTREAM.md](third_party/go-nfs-UPSTREAM.md), and run upstream's tests with the patches applied. Editors
format Go on save reformat untouched lines of the copy; the rebuild procedure undoes that.

## Smoke test against a real mount

Unit tests cannot cover the kernel NFS client. Before changing anything in `internal/server`, `internal/fsys`,
`internal/platform` or the vendored go-nfs, mount a local WebDAV share and exercise it:

```sh
mkdir -p /tmp/davdrive-test/dav /tmp/davdrive-test/mnt
rclone --config /dev/null serve webdav /tmp/davdrive-test/dav --addr 127.0.0.1:18080 --user me --pass secret &

cat > /tmp/davdrive-test/config.toml <<'EOF'
[mounts.test]
url = "http://127.0.0.1:18080"
user = "me"
password_command = "printf secret"
mountpoint = "/tmp/davdrive-test/mnt"
EOF

export XDG_STATE_HOME=/tmp/davdrive-test/state XDG_CACHE_HOME=/tmp/davdrive-test/cache
davdrive --config /tmp/davdrive-test/config.toml mount
# create, append, rename, rm -rf, xattr -w, copy a large file; compare with /tmp/davdrive-test/dav
davdrive --config /tmp/davdrive-test/config.toml status
davdrive --config /tmp/davdrive-test/config.toml unmount
```

`--config /dev/null` keeps rclone away from your own rclone config. Check that no `._*` or `.DS_Store` file reaches
`/tmp/davdrive-test/dav`, and that a large file arrives byte for byte (`cmp`).

For the Linux path, run the same steps in a privileged Ubuntu container
(`docker run --rm -it --privileged -v "$PWD":/src ubuntu:24.04`) with a `GOOS=linux` build, `nfs-common`
installed, and a non-root user with `sudo`.
